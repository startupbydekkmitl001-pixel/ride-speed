# Private candidate preparation

`prepareCommunityPhoto(source, assertCurrent)` uses installed Expo SDK 57 APIs. `source` contains the observed local picker URI, dimensions, optional byte count, and on Web the actual picker `File`/`Blob` as `webFile`. It rejects remote HTTP input, checks actual input File/Blob size ≤20 MiB and picker dimensions ≤40 MP, renders pixels, checks actual decoded dimensions, then resizes to a maximum 1600 px edge. It tries JPEG qualities 0.86, 0.72 and 0.58 against actual output bytes; an image still over 1 MiB is rejected with its original picker source untouched.

The result contains a private temporary `uri`, exact `bytes`, a local candidate descriptor `{mime,sha256,byte_count,width,height,blurhash}`, and idempotent `dispose()`. Root copies the bytes and descriptor durably under the initiating account before disposing the temporary. There is no `validation:'decoded_jpeg_v1'` claim here. The canonical Edge must verify uploaded bytes and return the validated descriptor before a photo becomes ready. Its pixel-derived BlurHash may differ from the local optional placeholder; MIME, digest, byte count and dimensions cannot change during reconciliation.

The caller's `assertCurrent` must pin both account generation and current screen/activity/movement policy. It runs before work and after every asynchronous boundary, including rendering, saving, reading, digest, optional BlurHash and cleanup. Stale candidates are discarded. Only this helper's newly generated cache files/Blob URLs are tracked for cleanup; picker originals and durable owner files are never deleted. Shared image/context references are released in `finally`.

SDK evidence: installed ImageManipulator's iOS implementation writes `UIImage.jpegData` and Android writes `Bitmap.compress`, while Web saves the rendered canvas Blob. The helper hashes those actual output bytes through `Crypto.digest(SHA256, bytes)`, not a Base64 string. [ImageManipulator 57](https://docs.expo.dev/versions/v57.0.0/sdk/imagemanipulator/) documents the contextual render/resize/save APIs. [Crypto 57](https://docs.expo.dev/versions/v57.0.0/sdk/crypto/) documents typed-byte digests. [Expo Image 57](https://docs.expo.dev/versions/v57.0.0/sdk/image/) supports genuine BlurHash generation on iOS/Android; Web uses `null` and a neutral placeholder until canonical server output exists.

Tests exercise actual source with SDK ports mocked and synthetic real JPEG fixtures. Native pixel encoding, orientation, metadata rejection, six-photo memory, CPU, offline restart and device performance still require native/deployed acceptance. Picker `exif:false` alone is never the privacy proof.
