# M7 Community — approved product policies and deployed additive 011/012 wire

Root approved the audience, scoring, immutable attachment and image-validation policies on 2026-10-01. The named RPCs/envelopes below remain a proposal until root/backend review freezes `types.ts`. This document does not claim that these functions are deployed.

## Existing foundation and concrete gaps

- Migration 001 has genuine account-scoped posts, reports, private Storage, `(created_at,id)` Latest pagination and a signer that selects the parent through caller RLS. The UI must preserve those ownership checks.
- Migration 006 replaced raw saved-route stops with a 200 m privacy-trimmed snapshot. Legacy route metadata survives without geometry. Never reconstruct old hidden pins or join distinct fragments.
- Current composer reconciles ambiguous single-image upload/publish responses, but its attempt exists only in component memory. It uses 280 UTF-16-limited captions, one image, an editable claimed speed, Thai-only copy and no durable restart recovery. Current feed is a ScrollView and can show its empty message after a failed first read.
- Ordinary M2 ride summaries have immutable start-vehicle snapshots and exact revisions, but are private and self-reported. They cannot receive a verified badge because they were posted. Existing manually entered speed remains visibly self-reported on legacy reads.
- There are no ordered post-media, comments, likes, private saves or operation-receipt tables. Root owns durable drafts/outbox/provider/account cleanup; backend owns additive 011 tables, RLS and orphan cleanup.

## Content and attachments

New publication document version 1 contains `caption` (0–150 Unicode codepoints), `description` (0–4000), `visibility` (`private|friends|public`), `ride` (null or exact owned `ride_id,ride_revision`), `route` (null or exact owned `route_id,route_revision`), `include_ride_route` (boolean), and ordered `media_ids` (0–6 unique UUIDs). At least one non-whitespace text, attachment or image is required. Reject malformed UTF-16 and unsafe control bytes. Do not normalize or letter-space Thai. Existing captions up to 280 codepoints remain readable with `content_version:0`; new writes never truncate existing data.

The server freezes the real ride summary and its vehicle snapshot at publication. It derives distance, duration, average and maximum from that exact private source revision; absent values remain null. The quality is `self_reported` with independent immutable-source identity/digest, never verified-native. Include the ride's route only after the publication review discloses location sharing: decode independent fragments, trim the first and last 200 m conservatively, preserve every gap, drop raw start/end points, pins, place IDs and private bounds. Insufficient remaining geometry is `hidden`. An explicitly selected saved route similarly uses the exact current route revision's safe projection. Prefer an explicitly selected saved route over the derived ride path when both are present. These immutable post copies follow the post audience; editing a source ride/route must not silently change a reviewed publication.

Publishing is independent of Ranked publication, evidence retention, Friends presence and live location. Default Friends. A Private post is visible only to its owner and excluded from shared comparisons. Audience changes and deletion are separate CAS mutations; publication text/media/attachments stay immutable after publish in M7. Draft edits remain possible locally before the frozen publish operation.

## Feed and detail readers

- `rs_community_feed(p_filter:{schema_version:1,mode:'latest'|'top_week'|'friends'},p_cursor:null|CommunityCursor,p_limit:20)`; maximum 30. Returns `{owner_id,server_now,filter,window,feed_revision,items,next_cursor}`.
- `rs_community_post(p_post_id)` returns `{owner_id,server_now,post}` or a stable unavailable error. Never send owner-only draft/private geometry in a public feed DTO.
- `rs_community_comments(p_post_id,p_cursor:null|{created_at,id},p_limit:30)` returns `{owner_id,server_now,post_id,content_revision,items,next_cursor}`. Parent visibility/block/moderation/account-deletion checks apply on every page and to each author.
Saving exposes the canonical saved flag only. No saved-collection API is wired without a separately frozen backend contract.

Latest and Friends use descending `(created_at,post_id)` keysets with a fixed server `as_of`. Friends includes self and currently accepted friends, while rechecking the actual post audience and blocks. Top this week uses Asia/Bangkok Monday midnight, a half-open UTC week and only posts created in that week. Its score is the number of unique eligible likes received in that week; descending score then created_at and post_id are deterministic display order. Self-likes do not contribute. Comments and saves do not affect the score. The UI states this criterion. Hidden, deleted, blocked or ineligible authors/likes cannot influence the visible score.

Opaque-safe typed cursors bind owner, mode, server window/as_of, feed revision and exact last server ordering position. The server must reject stale permission/score/content/filter changes with `COMMUNITY_CHANGED`; root refreshes page one. Never calculate position or Top rank from loaded rows. Feed rows include canonical like/comment counts, viewer-liked/saved flags, exact content/engagement revisions, and sanitized media descriptors. They never include Storage paths or signed URLs. Legacy claimed speed is a distinct nullable legacy field with an explicit self-reported label.

## Durable publication and interactions

`rs_community_attachment_review(p_ride,p_route,p_include_ride_route)` accepts only the explicitly selected immutable bindings and returns `{owner_id,server_now,ride,route}` using the same private-to-shared projection as publication. The caller sends no geometry. An explicit separate saved route wins over ride-route geometry. `include_ride_route:true` still requires the selected ride binding. A ride-derived route may have `category:null` when the original recording has no vehicle; saved and legacy route categories remain required. The strict service export is `getCommunityAttachmentReview(scope,session,selection)`.

- `rs_community_reserve_post(p_post_id)` creates/reuses an owned unpublished draft. UUID reuse by another owner fails. It returns only the owned ID, draft revision and status.
- `rs_community_reserve_media(p_post_id,p_media_id,p_descriptor)` accepts JPEG SHA-256, byte count and declared dimensions. Returns `{post_id,media_id,bucket:'ride-post-media',path,expires_at,state:'reserved'|'committed'}` with a server-assigned owner/post/asset path. Same ID+descriptor retries reuse it; changes/cross-owner reuse fail. Storage is private, JPEG only, each object at most 1 MiB, `upsert:false`.
- `community-media-commit` Edge POST `{postId,mediaId}` downloads that reservation's object, validates its actual bytes/digest/decoded pixels/dimensions/metadata, and commits canonical descriptor/blurhash. One photo per request. It accepts no path. Only complete verified assets may be in a published ordered manifest.
- `rs_community_mutate(p_operation_id,p_request)` has desired-state/idempotent operations: `publish`, `audience`, `delete_post`, `like`, `save`, `comment`, `delete_comment`, `report`. Request UUID and exact reviewed bindings are durable before send. `rs_community_operation(p_operation_id)` returns the caller's same receipt or null. Same UUID+different body is a conflict. Receipts never confer success merely because a local operation is queued.
- Publish freezes the document and exact reserved draft revision. Like/save supply the desired boolean and exact content revision, not an ambiguous toggle. Comment supplies its own UUID, body up to 1000 codepoints and exact parent content revision. Report target is post or comment with fixed spam/harassment/privacy/dangerous/other reason and optional detail up to 1000.
- Applied receipt contains owner, operation ID, original request, applied_at and a typed result with exact canonical revision/state. Error envelope is `{error:{code,retry_after_ms?}}`; rate backoff comes from the server. Unknown transport outcomes remain pending. Optimistic overlays derive from pending desired-state operations and roll back only on a definitive rejection. No positive badge/count claims before canonical acknowledgement.
- Block/unblock remains root's current 007 SocialProvider operation: freshly read pair generation, null only for actual absent pair. Community must not bypass it or call superseded legacy RPCs. A block immediately invalidates feed, details, comments, counts and private media rendering.

## Private image delivery and validation

`community-media-url` Edge POST `{postId,mediaId}` rechecks current parent/asset/author visibility, then returns `{postId,mediaId,sha256,url,expiresIn:60}`. It never accepts a path. Client validates the project HTTPS origin and exact private bucket owner/post/media path, captures owner generation, and uses a bounded in-memory URL cache keyed by owner/post content revision/asset digest. No signed URL in local drafts, route params, logs or deep links. Lost/expired URL reload is bounded while visible; a revoked account/post/block immediately removes the image and cached URL. Historical signed URLs cannot be cryptographically revoked during their short TTL, so this is disclosed accurately.

Client picks/re-encodes pixels to JPEG with maximum edge 1600 and 1 MiB per image; strips input metadata through re-encoding, then the server verifies the bytes. Raw picker input caps (20 MiB/40 MP) avoid unbounded client work. The six-photo total is at most 6 MiB. Native Expo Image can generate a local BlurHash; its documented method is not available on Web. Web uses a neutral placeholder until a canonical server-produced verified-pixel BlurHash exists, without a fabricated hash. Draft preview is private device-local data, not a cloud success.

Bounded server candidate: pinned pure-JS `jpeg-js@0.4.4`, strict decode with `useTArray:true`, `formatAsRGBA:true`, `tolerantDecoding:false`, `maxResolutionInMP:2.56`, `maxMemoryUsageInMB:64`. Before decoding, enforce actual byte cap, JPEG marker/framing/components/dimension limits, one image, no trailing payload, and reject EXIF/XMP/APP13/COM/unknown metadata; fixed JFIF/Adobe colour headers require exact allowlist validation and no embedded thumbnail. Afterwards cross-check decoded dimensions/digest and derive canonical placeholder pixels. Header sniffing alone is not validation. Test native re-encode variants plus corrupt entropy, wrong MIME, bombs, metadata, digest mismatch and malformed/trailing data. Hosted worst-case CPU remains an acceptance gate: one photo per request must fit the platform, otherwise lower the cap or prove a deployed bounded decoder alternative.

Primary sources checked 2026-10-01: [Supabase dependency support](https://supabase.com/docs/guides/functions/dependencies) supports npm modules; [Edge limits](https://supabase.com/docs/guides/functions/limits) documents 256 MB memory, 2 s CPU/request and no sharp/libvips threading. [JPEG-js documentation](https://github.com/jpeg-js/jpeg-js) documents synchronous pixel decode and explicit memory/resolution/tolerance options. [Expo Image 57](https://docs.expo.dev/versions/v57.0.0/sdk/image/) documents Android/iOS-only BlurHash generation and cross-platform display. [Expo Image Manipulator 57](https://docs.expo.dev/versions/v57.0.0/sdk/imagemanipulator/) supplies pixel transformation/re-encoding; picker `exif:false` alone is not the server privacy proof.

## UI and delivery boundaries

Approved reservation amendment: immutable committed photos return `state:'committed'` and remain reusable after the original reservation expiry; reserved photos expire only after exact owner/post/descriptor identity is checked. `COMMUNITY_CAPACITY` is a fixed rejection for the project-specific 256 MiB post-media and 768 MiB aggregate actual-plus-reserved application storage budget. These are pilot quotas, not a billing guarantee or an assertion about unrelated project objects. Local drafts remain recoverable.

Stateless components receive a typed owner-generation parent port. They repeat current/focus/foreground/moving guards at retained callbacks and after local async reviews. Root still authoritatively checks and persists every operation. Feed uses a virtualized list with stable callbacks, real pagination and successful-read-only empty states; cached/offline rows are visibly stale. Private images mount only while their row/detail is visible. No video or live map canvas per feed row. A static route outline preserves distinct fragments; an explicit detail action may open the existing bounded map. Existing max-two MotionProvider still owns all looping materials.

Composer has a visible 150-codepoint counter, read-only attached summary, vehicle/source labels, six ordered/removable photo tiles, audience review and clearly separate local/upload/pending/published states. Held pick/review requests invalidate on input, close, background, movement or owner changes. Published or ambiguous pending attempts are not silently discarded. Detail offers canonical likes/comments/save, safe share, report, block and owner-only audience/delete confirmations. Route/post preview never introduces fake people, counts, ranking or geometry.

Deep link uses the allowlisted active app scheme and opaque post UUID (`ridespeed://community-post?postId=<UUID>` or the matching development scheme). The native Router bridge validates that exact host and query before navigation. It carries no signed media URL/token, never changes audience and always reads through the current viewer's backend permission. Missing/private/moderated posts show unavailable, not a synthetic post.

Required acceptance: scoped service decoder tests against real SDK requests; caption/Thai/emoji boundaries; six-photo ordering and ambiguous upload reconciliation; immutable attachments and route-gap/200 m privacy; child visibility/count/signature/block/deletion tests; durable optimistic rollback; stable keysets and Top week boundaries; actual rendered first-read failure, stale callbacks, movement, interrupted async sheets and raw native View-child regressions. Root performs hosted signed-account acceptance without fake public content, plus real-device image/performance/offline restart checks.
