# M7 Community and private photo contract

Canonical client DTOs are in `ExpoRideSpeed/src/features/community/types.ts` and its `CONTRACT.md`. Additive011 preserves deployed001–010 bytes. Ordinary ride summaries stay self-reported; only an explicit publication creates a separate immutable Community snapshot. No photo, caption, saved route or catalog selection proves speed, vehicle ownership or a competitive result.

## Owner drafts, immutable publication and interactions

`rs_community_reserve_post(p_post_id)` returns `{owner_id,post_id,revision,state}`. The owner chooses and persists one UUID before the first request. Exact existing ownership replays before admission; another owner cannot bind that UUID. New drafts require a real profile and start at revision0.

`rs_community_mutate(p_operation_id,p_request)` returns an exact `{owner_id,operation_id,request,applied_at,result}` receipt or the fixed error envelope. `rs_community_operation(p_operation_id)` returns the same owned receipt or null. Every request has schema_version1, an exact action, post_id and expected_revision. Publish requires revision0 and its explicit document; other actions require revision≥1. Unknown fields and discriminants reject before admission. Persist the original operation/request unchanged through timeout, restart and account-scoped retries. Replay precedes quota and current state checks; a changed request under the same UUID fails `COMMUNITY_OPERATION_CONFLICT`.

Publish freezes caption≤150 Unicode codepoints, description≤4000, private/friends/public visibility, optional exact owned ride/route bindings, explicit ride-geometry choice and0–6 ordered unique committed image IDs. Empty text requires a genuine attachment. No client-generated summary, geometry, digest authority or photo URL is accepted. Publication is immutable; audience and delete are separate content-revision CAS operations. Both increment exactly once, including legacy posts and a same-audience write. Unchosen candidate photos become obsolete only after successful publication. Delete makes the post inaccessible before binary cleanup; replay of a prior receipt cannot revive it.

Like and save use desired booleans rather than a toggle. Comment writes use a persistent unique comment UUID and≤1000 codepoints; only its author can delete it while the current parent/child ACL still authorizes it. A post owner can report or block. Report accepts a post or current comment, fixed reason and≤1000-codepoint detail. Reports never auto-approve, auto-hide or rewrite proof; only service-side moderation reads the queue and changes visibility. Account deletion, current block and current friendship are rechecked for every new transition. Recognized business rejection rolls back the inner transition but keeps outer admission. Unexpected SQL/transport failure is uncertain and must retain the immutable pending request.

## Server attachment review

`rs_community_attachment_review(p_ride,p_route,p_include_ride_route)` returns `{owner_id,server_now,ride,route}` using the same helper as publish. Bindings are null or `{ride_id,ride_revision}` / `{route_id,route_revision}`. Exact current ownership/revision is required; later source changes reject with `COMMUNITY_SOURCE_CHANGED`. A selected saved route wins over ride-derived geometry, even when include_ride_route is true. An unchosen route is never read implicitly.

Ride statistics come from the private M2 row and remain `self_reported`; a missing immutable vehicle/category stays null. Recorded fragments are decoded independently and trimmed geodesically by at least200m from each end, with disconnected gaps retained. Short, unrepresentable or more-than32 drawable parts are hidden as a whole. There is no fabricated connection or selective truncation. Saved routes use the existing sanitized private-route projection. No raw stop labels/place IDs, original bounds, private endpoint geometry, raw GPS samples or evidence paths are returned. Endpoint trimming does not conceal sensitive stops in the middle of a route.

Finite owned source choices already exist: `rs_list_ride_summaries` and `rs_list_routes_owner`. Show a genuine current server binding, then review it; a stale local-only draft is not publishable. Published snapshots retain their original revision when the private source is edited later.

## Feed, detail, comments and owner privacy settings

`rs_community_feed(p_filter,p_cursor,p_limit)` uses schema_version1 and mode latest/top_week/friends, with1–30 rows. Latest and Friends order by exact UTC microseconds and post UUID descending. Top this week uses Asia/Bangkok Monday midnight and half-open boundaries: posts created in this week, unique eligible non-self likes received in this week, score descending then time/ID. Current blocked/deleting users do not count. Public/private/friend visibility remains current at every read.

The owner/mode/window/as_of/hash-bound cursor expires after ten minutes and invalidates on relevant content, profile, eligibility, counts or private save changes. Full candidate count is bounded10,000; excess returns unavailable. Fingerprints use compact revisions/current eligibility/profile/counts, and full descriptions/media/coordinates are materialized only for the selected≤31 rows. The20-row client page does not imply a measured large-board query cost. `rs_community_post(p_post_id)` returns one currently viewable canonical detail. `rs_community_comments(p_post_id,p_cursor,p_limit)` orders exact `(created_at,comment_id)` ascending, up to30, with current parent/child ACL. Feed/detail return no bucket path, signed URL or arbitrary image reference.

Separate owner metadata prevents a hidden post from trapping an old sharing preference. `rs_community_owner_posts(p_cursor,p_limit=20)` returns `{owner_id,server_now,items,next_cursor}`, with1–30 metadata rows ordered exact `(updated_at,post_id)` descending. The cursor is `{owner_id,updated_at,post_id}`. Each item contains only `{post_id,content_revision,visibility,state,updated_at}`; list states are published/hidden/deleted and reservation drafts are excluded. `rs_community_owner_post(p_post_id)` returns `{owner_id,server_now,post}` with the same metadata, additionally allowing read-only draft/revision0. Other-owner IDs remain unavailable. Use this getter only for owned audience/delete preflight; normal interaction and image readers still use viewer ACL. Hidden content, media, captions and geometry are never exposed through these settings APIs.

Legacy content_version0 remains genuine legacy content. Its old≤280-caption/manual speed is labeled distinctly. An old route keeps only a valid title/category/revision with source legacy, source_id null and geometry unavailable; no provider or trimming proof is invented. Old JPEG/PNG/WebP images have opaque server-assigned media IDs, `legacy_unverified` validation, and null digest/size/dimensions/placeholder. Unsafe legacy control characters are removed from read copy, and malformed old route references become unavailable; stored originals remain intact. New writes never inherit these relaxed legacy bounds.

## Immutable photo reservation, pixel validation and signing

`rs_community_reserve_media(p_post_id,p_media_id,p_descriptor)` returns `{post_id,media_id,bucket,path,expires_at,state}`. Descriptor keys are exactly mime,sha256,byte_count,width,height,blurhash. New images are JPEG≤1MiB, edges≤1600px, actual-byte SHA256 and nullable client placeholder. Bucket is private `ride-post-media`; path is exactly `ownerUUID/postUUID/mediaUUID.jpg`. Owner/post/UUID/original descriptor is immutable. State is reserved or committed. Reserved expiry is24h; committed replay survives that original expiry. An expired uncommitted reservation must use a new persisted UUID after definitive expiry, never extend or rebind the old one. Draft candidate count is24; the published manifest remains six. Candidate replacement does not mutate an unknown pending publication.

Upload uses current owner INSERT only, reservation exact path, no upsert and no UPDATE/DELETE policy. The current owner may read pending/committed bytes for response-loss recovery. `community-media-commit` takes exactly `{postId,mediaId}` plus the initiating Auth JWT. Its service-only two-minute claim lease binds the authenticated owner and immutable reservation. It downloads only a server-issued, same-project, sixty-second URL with redirect disabled, a ten-second timeout and a hard1MiB stream cap. The pinned strict decoder verifies actual entropy/pixels, declared digest/dimensions and metadata restrictions; the server derives the final BlurHash. Header declarations and a native compression response are not pixel-validation authority. Response is `{post_id,media_id,descriptor}`. A committed retry returns the canonical descriptor without redownload; an exact existing Storage object must still exist with the committed size/MIME.

The vendor is upstream jpeg-js0.4.4 with only ESM export and strict unused-entropy/alignment checks; the exact diff and upstream/canonical hashes are in `functions/_shared/vendor/README.md`. One exact all-one byte-aligned codec padding byte is permitted, never arbitrary unread payload. JPEG grayscale/progressive fixtures are entropy-decoded. EXIF/XMP/ICC/comments/APP13, thumbnail payload, trailing concatenation and unreviewed encodings reject. This removes explicit metadata/unread payload; it does not prove absence of hidden information in valid pixels or steganography. Retain both BSD and Apache notices in redistribution and standalone dashboard bundles.

`community-media-url` takes the same exact body and returns `{postId,mediaId,sha256,url,expiresIn:60}`. It checks current parent visibility/block/membership/account status and included committed media, signs only the stored server path, then repeats the caller-JWT check after signing. Legacy SHA remains null. Already-issued URLs can survive revocation until expiry; clients must stop rendering cached URLs immediately when authorization changes. No client service key or caller-supplied path is accepted.

## Capacity, retention and operation

New post media has dedicated256MiB reserved+actual headroom. All six application buckets share768MiB: ride-avatars,vehicle-photos,ride-evidence,ride-race-evidence,ride-community,ride-post-media. Account→global locks serialize new allocations across avatar, Garage, legacy evidence, race evidence and Community wrappers. Original bodies/signatures/grants remain private immutable predecessors. Exact replay/collision/identity checks precede admission. An unresolved photo holds its1MiB bucket maximum and unresolved evidence holds2MiB; once genuinely committed, authoritative actual size counts once per bucket/path. Unknown sizes consume the budget and fail closed. Existing bytes, orphans and still-retained binaries continue counting until real cleanup. `COMMUNITY_CAPACITY` preserves local bytes; remove/review unwanted content or wait for operated cleanup. The app budget is not organization billing authority and does not cover unrelated buckets.

Reads share60/minute,5000/day owner,50000/day project. Controls share60/minute,500/day owner,10000/day project. New drafts20/minute,100/day owner,2000/day project; new photo reservations30/minute,120/day owner,2000/day project. Signer checks60/minute,3000/day owner,30000/day project; each URL uses two checks. UTC admission buckets return explicit retry_after_ms only for rate errors. Replays are free. Compact exact receipts/reservation tombstones persist until account deletion; monitor database size and do not prune an active outbox's promised retry window.

`community-media-cleanup` requires only the existing service secret and POST; ordinary JWTs cannot invoke it. Each call claims≤20 expired/obsolete/invalid or seven-day unpublished committed binaries under token leases, removes through Storage, then ACKs only genuine absence. Immutable retired media IDs remain tombstones, preventing path/owner rebinding. Published included media is never janitor-selected. Account deletion lists new bucket reservations and orphaned owned paths, requires binary absence, then removes dependent cross-owner receipts/comments/reports before the established SQL→Auth phase. No new delete-account deployment is needed.

Before broad release, operate and observe a separately authorized protected cleanup schedule, keep private buckets/RLS/exposed-schema restrictions, inspect current organization Storage/database/egress/function usage, and test actual native/browser output plus hosted CPU and signed-image revocation. Definitions/local tests do not install Cron/Vault, invoke permanent deletion or authorize cloud fixtures. Read-only `ops/m7-community-readiness.sql` reports only aggregate counts/grants/policy/capacity. No extra account/key is required for these handlers. Anonymous user handlers must return401 and cleanup must return401 SERVICE_AUTH_REQUIRED when gateway settings are prepared; disabling the legacy gateway never removes handler authentication.
